# Pet Insurance Loss-Ratio Forecaster

Projects the 12-month loss ratio (claims ÷ premium) of pet-insurance partner groups on fully synthetic data, blending each group's own experience with its segment benchmark using actuarial credibility. Covers the full workflow: a messy-data generator, a cleaning pipeline with a data-quality gate, the projection model, a back-test, a FastAPI service, a React dashboard, monitoring, Docker, and CI.

> All data is generated by `petlr.generate`. No real people, pets, insurers, or claims are involved.

## Features

- **Synthetic data generator**: ~300 partner groups (10–2,000 pets) over 24 months, with frequency × severity claims, seasonality, an 8%/year cost trend, random large claims, payment lags, and a late cost shock in one region. It deliberately plants data problems (duplicate rows, pets from cancelled groups, late-paid claims, one-day date shifts, invalid start dates) and records ground-truth counts.
- **Cleaning pipeline and quality gate**: pandera schemas report every problem found, the pipeline fixes each known issue, and a strict output schema fails loudly on anything unexpected.
- **Credibility-weighted projection**: `Z × own experience + (1 − Z) × segment benchmark`, with `Z = min(1, √(pet-months ÷ threshold))`, then trend, seasonality, and a large-claim load.
- **Back-test**: hides the last 6 months and compares the credibility blend against own-data-only and benchmark-only models.
- **API**: FastAPI with assumptions (trend, credibility threshold, premium change, at-risk level, horizon) as validated query parameters, segment filters, breakdowns, and CSV export.
- **Dashboard**: React with assumption sliders, headline tiles, a history and projection chart with a table view, credibility shown beside every number, at-risk flags, a step-by-step group breakdown, and light and dark themes.
- **Monitoring and operations**: data freshness, PSI drift, segment drift, and actual-vs-expected checks; a daily Prefect schedule; Docker Compose; and GitHub Actions CI.

## Method

| Step | Approach |
|---|---|
| Claim timing | Claims are booked to the month of the vet visit, not the payment month |
| Late claims | Completion factors (IBNR) gross up recent months based on how complete older months were at the same age |
| Normalization | Experience is expressed per pet per month (PPPM) so groups of different sizes are comparable |
| Trend and seasonality | Annual trend estimated year over year and a monthly seasonality index; both are removed before comparing months and reapplied when projecting |
| Large claims | Each claim is capped at $5,000 in a group's own experience; the excess is added back as a portfolio-wide load |
| Credibility | `Z = min(1, √(pet-months ÷ 2,000))`; the 2,000 pet-month default was tuned by back-test |
| At-risk flag | Projected loss ratio above 85% (configurable) |

The back-test rebuilds history as known at the cutoff, excluding claims paid after it, so no future information leaks into the projection.

## Results

On the default synthetic data (back-test cutoff 2026-03-01, 6-month holdout, 269 groups scored):

| Metric | Value |
|---|---|
| Problems caught by the gate | 1,093 duplicate claims, 28 duplicate premium rows, 187 + 1,536 one-day date shifts, 5,450 cancelled-group pets, 7,680 late-paid claims, 7 invalid start dates |
| Estimated trend (full history) | 7.9%/year (true value: 8%) |
| Projected 12-month loss ratio | ~73.5% |
| Back-test group WAPE | credibility **21.4%**, own-only 21.8%, benchmark-only 26.6% |
| Back-test WAPE, small groups (Z < 0.3) | credibility **41%**, own-only 69%, benchmark-only 43% |
| Monitoring | Flags the planted West-region cost shock (+24% vs +12% elsewhere) |

Credibility weighting gives the lowest error overall and avoids the large errors of own-data-only projections for small groups.

The back-test shows a −7.6% portfolio bias (under-projection). Two causes: only 18 months of history were available at the cutoff, so the trend estimate was 3.9% instead of 8%, and the West-region shock began after the cutoff.

## Quickstart

Requires conda and Node.js 18+ (22 recommended).

```bash
conda create -n pet-insurance-forecaster python=3.12 -y
conda activate pet-insurance-forecaster
pip install -r requirements.txt
pip install -e .
cd frontend && npm install && cd ..
cp .env.example .env    # optional; contains no secrets
```

Run the full pipeline once (generate, clean and gate, projection snapshot, back-test, monitoring):

```bash
python -m petlr.flows
```

Start the API and dashboard in two terminals:

```bash
uvicorn petlr.api:app --reload --port 8000
```

```bash
cd frontend && npm run dev
```

The dashboard is at http://localhost:5173 and the API docs at http://localhost:8000/api/docs.

Individual steps:

```bash
python -m petlr.generate      # writes data/raw/ and prints planted problems
python -m petlr.pipeline      # cleans, runs the gate, prints every issue caught
python -m petlr.backtest      # error for credibility vs own-only vs benchmark-only
python -m petlr.monitoring    # freshness, drift, and actual-vs-expected checks
```

### Daily schedule (Prefect)

Schedules require a persistent Prefect server:

```bash
prefect server start                                                       # UI at http://localhost:4200
PREFECT_API_URL=http://127.0.0.1:4200/api python -m petlr.flows --serve   # second terminal
```

### Docker

```bash
docker compose up --build
```

Website at http://localhost:8080, API docs at http://localhost:8000/api/docs, Prefect UI at http://localhost:4200.

### Example API calls

```
GET /api/segments?region=West&deductible=500&trend=0.08&threshold=3000
GET /api/segments/breakdown?by=species_mix
GET /api/groups?at_risk_only=true&sort=-proj_lr
GET /api/groups/G0042?premium_change=0.05
GET /api/export.csv?size=small&size=medium
GET /api/backtest      GET /api/monitoring      GET /api/quality
```

### Deploying on Render (free tier)

Free instances sleep when idle, so the first request can take 30–60 seconds.

1. **API**: create a Web Service from the repo with the Docker runtime and the Free instance type. Set the Docker command to
   `sh -c "python -m petlr.generate && python -m petlr.pipeline && python -m petlr.backtest && python -m petlr.monitoring && uvicorn petlr.api:app --host 0.0.0.0 --port $PORT"`
   so the container generates its own synthetic data on start. Verify with `https://<api-name>.onrender.com/api/health`.
2. **Website**: create a Static Site with root directory `frontend`, build command `npm ci && npm run build`, and publish directory `dist`. Add a rewrite from `/api/*` to `https://<api-name>.onrender.com/api/*` and from `/*` to `/index.html`.

The daily Prefect schedule is not part of this setup; each restart regenerates the synthetic data.

## Design decisions

- **Synthetic data with known ground truth.** The true trend (8%) and the West-region shock are known, so the pipeline, model, and monitoring can be checked against them.
- **Report every data problem.** pandera's lazy validation collects all failures; a separate strict schema on the output (including a billed-pets = enrolled-pets reconciliation) stops anything unexpected from reaching the model.
- **Back-test-driven tuning.** The back-test led to the 2,000 pet-month credibility threshold and to year-over-year trend estimation.
- **Accessible risk flags.** At-risk groups are marked with an icon and label, not color alone.

## Limitations and future work

- All results are on synthetic data and do not reflect any real portfolio.
- Trend estimation is unreliable with short history: at the back-test cutoff (18 months), the estimate was 3.9% against a true 8%, producing a −7.6% portfolio bias.
- Shocks that begin after the projection cutoff are not anticipated; monitoring detects them after the fact.
- The free Render deployment does not run the daily schedule.
